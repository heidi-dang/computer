---
name: Build Agent evidence
description: Evidence boundary for the sequential Build Agent implementation loop.
---

The Build Agent may compose native coding, diagnosis, repair, and tester children, but
completion must be decided from durable child lifecycle state and authoritative verifier
evidence. Compatibility return values are informational and specialist prose is never
completion proof.

**Why:** The authenticated gateway preserves legacy string return types for some
specialists, while durable FlowDeck operations carry the identity-bound outcome needed
to prevent false successful builds.

**How to apply:** Keep each Build phase sequential and parent-durable; require the
child run and every child operation to be terminal and authoritative before recording
the parent phase as successful. Re-run the exact failed check after bounded repair.
