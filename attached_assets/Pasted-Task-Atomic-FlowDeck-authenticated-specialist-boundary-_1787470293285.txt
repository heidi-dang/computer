Task
Atomic FlowDeck authenticated specialist-boundary refactor

Goal:
Make the authenticated FlowDeck gateway the only authoritative specialist execution boundary without expanding authority, adding a production route, or touching the separate Git adversarial-test milestone.

Current known-good baseline:
- FlowDeck/backend suite: 68/68 passing
- Authenticated gateway exists
- Durable workspace ownership checks exist
- Browser/read-only paths perform ownership revalidation
- debug-specialist is read-only
- Package-level lower-level execution exports were removed
- Native CPTR remains the only model/tool execution owner
- FDX and all higher-risk authority remain disabled

Known remaining problem:
These module-level functions remain directly callable and accept request dataclasses containing caller-controlled user_id/workspace:
- run_coding_specialist
- run_browser_debugger
- run_read_only_specialist
- run_mapper

This task must close that boundary atomically.

     - run_coding_specialist
     - run_browser_debugger

2. Refactor the native execution implementations to private/internal functions.
   Target conceptual boundary:

   authenticated CPTR request
       → authenticated FlowDeck gateway
       → canonical user/workspace authorization
       → private specialist native implementation
       → existing CPTR native execution loop

   Do NOT create another model/tool loop.

3. The private native implementations may receive already-authorized internal execution context, but they must not be exposed as public production authority boundaries.

4. Any compatibility-facing callable must require the authenticated CPTR request/context.
   - Derive user identity exclusively from authenticated CPTR request state.
   - Do not trust caller-supplied user_id as authority.
   - Do not trust caller-supplied workspace as authority.
   - Resolve the requested workspace against durable Workspace ownership.
   - Require exactly one canonical workspace for the authenticated user.
   - Fail closed for:
     - missing authentication
     - malformed authentication
     - wrong user
     - forged path
     - stale ownership
     - ambiguous ownership
     - missing ownership
     - mismatched runtime identity
     - mismatched runtime workspace
